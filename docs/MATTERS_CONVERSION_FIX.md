# 备忘安排为待办后的可见性修复

日期：2026-10-30。基线：`6b54759f76818a1cdbf83c0138092f88fde9ef0c`。
分支：`review/note-to-todo-visibility`；状态：`Awaiting User Acceptance`。尚未发布到 main。

## 复现与原因

在临时浏览器和独立 4184 Mock 服务中使用人工测试数据复现：

1. 点“安排为待办”时即写入了新待办，但默认 `dueAt:''`，确认前已经落库。
2. 保存后 `matterView` 仍为 `notes`，旧搜索/类型/日期条件也保留，导致新待办在当前列表中不可见。
3. 首页排除无计划日期的未完成事项，因而仍显示 `0/0`。
4. 手动设为今天后首页计数变为 `0/1`，但九条更早的逾期排在前面，八条预览仍不包含新事项。
5. 编辑期间若同步合并替换了数组对象，保存代码可能只修改旧引用，没有写回当前 S 数组。

这些复现使用通用测试文字，未读取用户截图之外的正式记录、浏览器存储或 Gist。

## 修复行为

- 新安排默认今天，可主动改未来日期或不设时间；按钮明确为“确认安排”。
- 创建/恢复先编辑草稿，确认后才保存，取消不新增或恢复待办。
- 已有有效关联直接查看同一待办，不重复创建；已删除关联只有确认才恢复。
- 确认后清空旧筛选，切换未完成视图并定位具体记录；显式选择已完成时切换已完成视图。
- 长列表会展开至目标所在位置，滚动预留现有顶栏高度；不会只停在前 40 条而隐藏新记录。
- 首页优先今日安排，并在本次操作中保留刚安排事项于八条预览；其余通过“查看全部”进入完整列表。
- 用户明确选择未来/无日期时，记录在未完成列表可见，不错误计入今日。过去已转为未定时间的记录不会批量补日期。
- 按 ID 写回当前数组，并参考当前记录的更新时间推进版本；不因同步替换对象而丢失本次保存。
- 原备忘内容保留，原有登录、存储路径、Gist/加密、导入导出及初始化顺序保持；CSS 与基线一致。
