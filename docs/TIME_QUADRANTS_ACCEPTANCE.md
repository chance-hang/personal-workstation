## 预览与使用

[打开电脑预览](http://127.0.0.1:4187/?mockSync=1#time-quadrants)。顶部有「待验收 · 本地模拟环境」提示。若本机服务已停止，从本验收仓库根目录在 PowerShell 运行下列命令，再打开链接。

~~~powershell
$env:PORT = '4187'
$env:MOCK_PREVIEW_ONLY = '1'
node tools/mock-sync-server.mjs
~~~

1. 在「事项 → 事项列表」选择待办录入一条模拟任务。打开详情，在「时间管理」分别判断重要和紧急，按需填写计划分钟。计划完成日期仍在原字段填写。旧待办和任一判断缺失的任务显示为「未分类」。
2. 进入「四象限时间管理 → 任务看板」。选择日期可查看该日计划、完成或重开、以及有实际用时的任务；「未安排日期」及「全部待办」覆盖其他场景。看板使用当前分类，可完成、重开并打开原任务详情。完成操作记为操作当天。
3. 点击「记用时」，选择同一条待办、实际发生日期、实际分钟，按需填备注及勾选临时插入。可为同一任务保存多段记录。当天录入默认带出当前象限，可改为发生时的象限；历史补记初始为「未分类」。更正可在明细中完成，首次录入时间保留。
4. 在「每日复盘」核对所选日的实际用时、相关任务状态和临时插入明细，填写未完成原因与次日调整。各象限汇总按记录上的发生时象限计算；没有用时记录时显示「未记录」。临时插入已计入实际用时总数。
5. 点击「导出」选择起止日期，下载或复制 Markdown。区间包含起止日。文档附任务 ID、当前分类、计划分钟、日期状态、实际用时及历史象限、发生日期与录入时间、复盘。没有相关记录的日期不生成区块。恢复或迁移完整数据使用「我的 → 导出 JSON」。

## 实现记录

| 需求 | 处理 |
| --- | --- |
| 复用待办 | 事项列表、四象限与番茄继续引用既有任务 ID。待办只增加独立的时间计划字段，保留原有计划日期与任务状态。 |
| 如实记录 | 手工记录有独立 ID，保存投入分钟、发生日期、录入日期和时间、临时标记、备注及象限快照。计划分钟和实际分钟分别存储。 |
| 每日复盘 | 根据存量数据计算日期状态和用时。复盘文字按天保存。缺少完成时间或状态证据时保留未知，当前计划日期改动后，旧日期的关联范围依现有记录计算。 |
| 备份与同步 | 新字段和两个记录集合进入现有 JSON、IndexedDB 镜像与加密业务状态。同步按 ID 保留不同记录，同一条用时或同日复盘取较新版本，删除同步保留标记。分类和计划分钟独立于待办正文与日期参加合并。JSON 合并导入补充缺失的时间计划并对新集合去重，保留已有同 ID 值。 |
| 手机与电脑 | 使用现有界面令牌和任务详情。桌面两列，手机纵向排列，日期和常用操作使用 44px 点击尺寸。 |

## 验证

- **20 组专项**，覆盖旧任务、分类与日期独立、同任务多段投入、历史快照、补记与更正、临时插入、复盘、Markdown、JSON 下载及两种导入、刷新、IndexedDB、双来源 Mock、同步时修改和删除、桌面与手机触屏布局。宽度为 320、375、390、414、768、1440 像素。专项脚本为 tools/check-time-quadrants.cjs。
- **回归**，通过 11 组备忘转换、6 组正式模式本地冒烟、8 组 Mock 隔离以及 6 种事项布局检查。沿用既有脚本的运行时断言，另用专项脚本比较本轮登录、加密、存储路径、备份入口和番茄等受保护源码。运行时拦截所有外部请求。
- **番茄现状**，在 Mock 中实际完成一段关联待办的专注及休息，确认专注保留任务 ID，休息未写入专注历史。另一来源只能同步用户勾选写入的工作日志，番茄历史仍只在计时浏览器。手工实际用时合计无变化。
- **界面**，查看了电脑和手机尺寸的渲染图。静态检测无 P0，未新增检测项。桌面展开侧栏时原有抽屉遮罩会拦截交互，本次将其限定到移动端。

## 实训记录口径

可以如实记录，本次由我提出任务分类、实际用时、每日复盘和区间导出的需求，并请 AI 核对现有代码、实现隔离版本和运行回归。当前证据是工具已通过本机模拟检查，真实实践成效需要由本人在使用后据实际记录总结。

实践时，早上从真实待办中选择当天事项，逐一判断重要与紧急，按需填计划分钟。实际工作按段记录投入，临时插入单独标记。日终核对完成情况，写未完成原因与次日调整。周期结束后按日期导出，报告引用实录中的任务、分钟、例外情况和调整。未记下的时间保留空缺，事后能确认的内容标记为回顾补记。
