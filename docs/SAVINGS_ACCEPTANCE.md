## 建议验收步骤

1. 打开账本的“存款”，添加“工资卡”和“微信”等账户，各填起始日期及起始余额。
2. 录一笔存入、一笔取出，再从工资卡转一笔到微信，确认总存款在互转前后不变。
3. 切换月份、年份和单个账户，核对净存入、起始余额、互转净额及期末余额。
4. 修改或删除一笔历史流水，查看后续月份是否随之重算。若导致某个历史日期透支，页面应拒绝保存并说明日期。
5. 打开顶部金额隐私，确认金额被隐藏、记一笔表单隐藏、账户及流水编辑不可用；关闭后草稿恢复。
6. 刷新页面，确认记录保留。可在“我的”导出完整 JSON 备份核对存款账户与流水。

## 统计口径

- 净存入＝存入－取出。
- 期末余额＝期初余额＋期间新增起始余额＋净存入＋互转净额。
- 全部账户互转净额为零；查单个账户时单列互转净额。
- 新账户起始余额单列，既不算当月存入，也不算当年净存入。
- 年末余额不累加各月余额。查询本月/本年时，截至今天；未记录期间不当成零，未来月份不估算。
- 停用账户保留历史和余额，并计入总存款；停用后不能新增流水，可重新启用。

## 实际限制

- 银行余额由手动记录计算，不自动连接银行；记录不全时不能等同于真实银行余额。
- 同一条记录并发修改按更新时间裁决；打开的编辑表单若期间同步到新版本，会拒绝旧表单覆盖。多个设备同时新增的取出合并后若出现余额不足，会提示核对，不自动删除用户流水。
- 沿用工作台原有 Gist 同步机制；真实跨设备、iPhone Safari 原生日期控件及键盘仍待用户验收，Mock 通过不代表这些真机项目已通过。
- 尚未授权发布。后续发布需明确 review 提交、范围和回滚点，再按既有流程执行。

## 重跑

在本目录执行 `node tools/check-savings.cjs`。测试工具依赖环境提供的 Playwright；Windows 可设 `NODE_PATH` 为运行时的 node_modules，`SAVINGS_BROWSER` 为可用浏览器绝对路径。

可选环境变量：`SAVINGS_ARTIFACTS` 为截图输出目录，`SAVINGS_PREVIEW` 为已生成离线 HTML 的绝对路径。离线生成沿用 `tools/build-review-preview.py`，参数为 `--label 存款记录 --namespace review_savings_20261118_`，输出到 checkout 外。
